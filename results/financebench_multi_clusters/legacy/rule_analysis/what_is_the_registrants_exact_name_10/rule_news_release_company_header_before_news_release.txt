Root cause: Wrong document-type assumption — rule is specialized for press releases,
not applicable to 10-K/10-Q filings.

The rule fires only when it finds a page-1 span whose text is exactly "news release"
(case-insensitive). Of the 10 documents in the evaluation set:
  - 8 are annual or quarterly SEC filings (10-K, 10-Q) — they never contain a
    "News Release" header, so the rule returns empty for all of them.
  - INTEL_2022Q4_EARNINGS is an earnings press release and does contain "News Release",
    so the rule retrieved 2 spans and correctly predicted "Intel Corporation". However,
    this document has no ground truth label, so the result is counted as incorrect
    regardless.
  - COSTCO_2023_8K_dated-2023-08-09 is an 8-K but apparently does not have a
    "news release" text span on page 1 matching the exact string.

The rule was generated because the 10 training documents included at least one earnings
release or 8-K format, leading the LLM to generate a document-type-specific rule. This
rule has zero utility across the dominant document type (10-K/10-Q) in the collection.

Fix direction: This rule should be discarded for 10-K/10-Q question slugs. It would
only be useful in a collection of press releases or 8-K filings. Alternatively, it
could be retained as a supplementary rule that runs after the primary rules fail, to
handle edge cases in mixed-format collections.
