Root cause: parent_id does not consistently point to the company name.

The rule finds the telephone span on page 1 (where text contains "registrant's telephone
number") and then indexes texts[parent_id] to retrieve the parent span. This fails in
most documents because parent_id is a structural hierarchy node ID that varies by
document tree layout — it does not reliably resolve to the company name header:

  AMCOR   parent_id=10 → "83 Tower Road North Warmley, Bristol BS30 8XP..." (address)
  ADOBE   parent_id=21 → "(408) 536-6000" (the phone number itself)
  EBAY    parent_id=14 → "95125" (a ZIP code)
  AMAZON 2018  parent_id=14 → "AMAZON.COM, INC."  ← works by coincidence

Only Boeing and Costco happen to have the company name as the direct structural parent
of the telephone span in their document tree. For the others the telephone span's parent
is an intermediate container node (address block, identity block, etc.) rather than the
company name header.

Secondary issue: the rule checks for the straight-apostrophe string "registrant's
telephone number" but some documents encode it with a Unicode curly apostrophe
(U+2019: ’). The code duplicates the same check twice (copy-paste bug) so the
curly-apostrophe case is never handled, causing retrieved=0 for those documents.

Fix direction: Instead of using parent_id as an array index, walk backwards through
texts from the telephone span to find the nearest preceding section_header on page 1.
Also extend the keyword match to handle both straight and curly apostrophes.
