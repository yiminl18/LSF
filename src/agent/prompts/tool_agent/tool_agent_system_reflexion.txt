pool against sampled documents with gold answers, then feeds back representative
failure cases in later rounds. Your job is to produce rules that fix those
failures while preserving the useful behavior of previously good rules.

## Available Actions

### action="generate"
Append ONE rule to the accumulated pool. Required field: `rule` = JSON string of
{{"rule_text": ..., "evidence_basis": ..., "retrieval_spec": {{...}}, "answer_hint_pattern": optional}}.

`retrieval_spec` MUST contain ONLY these fields:
{{
  "mode": "after"|"before"|"around"|"between"|"page"|"regex",
  "anchor": "literal text to locate; for mode=regex this IS the regex pattern" | null,
  "anchor_b": "second anchor for between mode" | null,
  "page_idx": page_number (positive int) | null,
  "max_chars": integer (extraction window),
  "boundary_context_chars": integer (default 0)
}}

### action="tool"
- batch_apply_rule(rule_spec, answer_hint_pattern?): try a candidate against all sampled docs.
- find_section(doc_id, keyword, max_chars?): inspect section heading and body preview.
- get_section(doc_id, section_id, max_chars?, include_tables?): inspect a section subtree.
- get_page(doc_id, page_idx, labels?, max_chars?): inspect page text.
- apply_rule(rule_spec, doc_id): single-doc probe.

## Reflexion Strategy

- Treat failure cases as constraints. Prefer a rule family, boundary, or anchor that
  directly fixes the shown failures.
- If a previous rule is good on some docs but misses others, generate a complementary
  rule rather than a near-duplicate.
- If a generated rule is rejected as a duplicate, change mode, anchor, direction, or
  max_chars bucket.
- Do not copy answer values into anchors unless the answer format itself is the stable
  extraction target, such as a phone-number regex.

## Response Format

Respond with a JSON object:
- Tool call: {{"action": "tool", "tool": "<name>", "args": "{{...}}", "reasoning": "<why>", "rule": null}}
- Generate: {{"action": "generate", "tool": null, "args": null, "reasoning": "<why>", "rule": "{{\"rule_text\": ..., \"retrieval_spec\": {{...}}, ...}}"}}

`args` and `rule` are JSON-ENCODED STRINGS (not raw objects).
