## Available Actions

### action="generate"
Append ONE rule to the accumulated pool. Required field: `rule` = JSON string of
{{"rule_text": ..., "evidence_basis": ..., "retrieval_spec": {{...}}, "answer_hint_pattern": optional}}.

`retrieval_spec` MUST contain ONLY these fields (extras like `pattern`, `page_constraint` will be silently dropped):
{{
  "mode": "after"|"before"|"around"|"between"|"page"|"regex",
  "anchor": "literal text to locate; for mode=regex this IS the regex pattern" | null,
  "anchor_b": "second anchor for between mode" | null,
  "page_idx": page_number (positive int) | null,
  "max_chars": integer (extraction window),
  "boundary_context_chars": integer (default 0)
}}
For mode=regex, put the regex into `anchor` — there is NO separate `pattern` field.
For mode=page, set `page_idx` to a positive integer (NOT page_constraint).

DIVERSITY GATE — your rule will be REJECTED if it duplicates an existing rule's
signature (mode, max_chars-bucket, anchor[:50] casefold). Vary at least one of:
- mode: after / before / around / between / page / regex
- max_chars bucket: small (≤200), medium (≤800), large (>800)
- anchor first-50 chars (case-insensitive)

LATE-PHASE AUTO-APPLY: in the LATE phase, each accepted rule is immediately run through
`batch_apply_rule` by the system. The returned coverage + `unmatched_doc_ids` + sample
matches will be appended to your next observation. Use this feedback to target the
unmatched docs with complementary narrow rules.

### action="tool" (diagnostics — does NOT add a rule)
- batch_apply_rule(rule_spec, answer_hint_pattern?): try a candidate against all sampled docs
  before committing it via `generate`. Returns coverage, per-doc preview, anchor_universality,
  optional answer_present_count + hint_extraction_warning. No LLM cost. Recommended in MID phase.
- find_section(doc_id, keyword, max_chars?): inspect section heading + body preview. `max_chars`
  is optional (default 1500, capped at 4000). No LLM cost. Capped at 4 consecutive calls.
- get_section(doc_id, section_id, max_chars?, include_tables?): PREFERRED navigation —
  fetch an entire section subtree body by its TOC `[id=K]`. Default max_chars=4000, cap 6000.
  Returns body + child_section_ids (for drill-down) + table_ids_in_body. No LLM cost.
- get_page(doc_id, page_idx, labels?, max_chars?): return all entries on a page, optionally
  filtered by labels (e.g. ["text","table"]). No LLM cost.
- apply_rule(rule_spec, doc_id): single-doc probe. No LLM cost.

## Strategy

- EARLY: don't over-think — produce rules across different anchor families (cover-page label,
  body section heading, page-mode fallback, regex value-match) and different window sizes.
- MID: call batch_apply_rule on your top candidate before generating to catch bad anchors
  cheaply.
- LATE: generate freely; the system's auto-apply feedback tells you exactly which docs
  your rule missed — your next rule should target those `unmatched_doc_ids`.
