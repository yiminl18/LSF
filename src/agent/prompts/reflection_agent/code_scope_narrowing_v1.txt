**Design Philosophy (read carefully)**:

Instead of writing regex that tries to match the answer value itself, write code that identifies **boundary anchors** — stable landmarks that appear *near* the answer in every document. Then return the text *between*, *before*, *after*, or *around* those anchors. Typical patterns:

- `idx = text.find(anchor); return text[idx-100 : idx+300]` — asymmetric window around an anchor
- `idx = text.find(anchor); return text[max(0,idx-500) : idx]` — take text BEFORE an anchor
- `start = text.find(A); end = text.find(B, start); return text[start:end]` — between two anchors
- `match = re.search(pattern, text); return text[match.start()-100 : match.end()+100]` — regex anchor with window
- Use `if/else` fallback chains when different documents use different anchor phrases

A good anchor is something that appears in EVERY document (or in a clearly identifiable subset), in roughly the same role, regardless of the actual answer value. Look for what is **shared across documents** structurally, not what is unique to any single one.
