# Evaluation Guide — Document QA

Result format, log format, scoring, and inspection commands for the FinanceBench QA eval.

---

## Result File Format

Results are written to `results/3M_2017_10K_results.json`.

### Ground truth schema (`sample_labels.json`)

```json
{
  "ADOBE_2022Q2_10Q.pdf": {
    "What is the registrant's exact name?": "Adobe Inc.",
    "What is the state (or other jurisdiction) of incorporation and the IRS Employer Identification Number?": "Delaware, 77-0019522",
    "What is/are the trading symbol(s) and listing exchange(s)?": "ADBE, NASDAQ",
    "What is total revenue for the most recent fiscal year?": "$4.39 billion"
  }
}
```

A dict keyed by **PDF filename** → dict of **question → answer string** (or list when multiple values).

### Agent output schema (`results/{doc}_results.json`)

Mirrors the ground truth structure, extended with per-query runtime metadata:

```json
{
  "3M_2017_10K.pdf": {
    "What is the registrant's exact name?": {
      "predicted_answer": "3M Company",
      "latency_seconds": 3.1,
      "input_tokens": 2840,
      "output_tokens": 115,
      "tools_used": ["filter_spans"],
      "num_iterations": 1
    },
    "What is/are the trading symbol(s) and listing exchange(s)?": {
      "predicted_answer": "MMM, New York Stock Exchange",
      "latency_seconds": 4.7,
      "input_tokens": 3210,
      "output_tokens": 98,
      "tools_used": ["filter_spans", "search_tables"],
      "num_iterations": 2
    }
  }
}
```

Field reference:

| Field | Type | Description |
|---|---|---|
| `predicted_answer` | string or list | Agent's answer; compared against ground truth |
| `latency_seconds` | float | Wall-clock time for this query |
| `input_tokens` | int | Tokens sent to the model across all iterations |
| `output_tokens` | int | Tokens generated by the model |
| `tools_used` | list[string] | Deduplicated list of LangChain tools invoked |
| `num_iterations` | int | Number of agent loop turns (tool call → result → next step) |

## Log File Format

One trace file per query: `logs/3M_2017_10K_{n}_trace.txt`

```
=== QUERY 7 ===
Question: What is/are the trading symbol(s) and listing exchange(s)?

--- Step 1 ---
Tool: filter_spans
Input: {"label": "table", "page_no_max": 2}
Retrieved: [{"text": "| Common Stock | MMM | New York Stock Exchange |...", "page_no": 1}]

--- Step 2 ---
Tool: search_tables
Input: {"keyword": "Trading Symbol"}
Retrieved: [{"text": "| Title of each class | Trading Symbol(s) | Exchange |...", "cells": [...]}]

--- Final Answer ---
Predicted: MMM, New York Stock Exchange
Latency: 4.7s | Input tokens: 3210 | Output tokens: 98 | Iterations: 2
```

## Running the Eval

### Full run

```bash
python agent.py 2>&1 | tee logs/agent_run.log
```

### Dry run — single query, verbose output

```python
response = agent_executor.invoke({
    "input": "What is the registrant's exact name?"
})
print(response["output"])
for action, observation in response["intermediate_steps"]:
    print(f"Tool: {action.tool} | Input: {action.tool_input}")
    print(f"Result: {str(observation)[:300]}")
```

### Enable LangSmith tracing (optional)

```bash
export LANGCHAIN_TRACING_V2=true
export LANGCHAIN_API_KEY="your-langsmith-key"
export LANGCHAIN_PROJECT="financebench-qa"
python agent.py
```

This gives you a full visual trace of every agent step in the LangSmith dashboard — tool inputs, outputs, token counts, and latency per step.

## Scoring

After the agent writes results, compare predictions against ground truth:

```bash
python scripts/score.py \
  --predictions results/3M_2017_10K_results.json \
  --labels data/financebench/sample_labels.json \
  --output results/scores.json
```

### Matching strategy by answer type

| Answer type | Match logic |
|---|---|
| Short string (name, ticker, state) | Exact or case-insensitive match |
| Number / amount | Normalize formatting (`$8,327M` ≈ `8327`), then exact |
| List of items | Set match — all items present regardless of order |
| Yes/No | Exact after normalizing to lowercase |
| Date | Normalized ISO date comparison |

## Metrics

| Metric | Description |
|---|---|
| Accuracy | % of questions with `predicted_answer` matching ground truth |
| Avg latency | Mean `latency_seconds` across 30 queries |
| Avg iterations | Mean `num_iterations` — lower = more direct reasoning |
| Tool distribution | How often each tool was invoked — reveals retrieval patterns |
| Avg input tokens | Proxy for context size per query |
| Failure rate | % of queries where `predicted_answer` is null or unparseable |

## Inspecting Logs

```bash
# View a single trace
cat logs/3M_2017_10K_7_trace.txt

# Find queries that never used search_tables (table retrieval skipped)
grep -L "Tool: search_tables" logs/3M_2017_10K_*.txt

# Find queries that took more than 3 iterations
grep -l "Iterations: [4-9]\|Iterations: [1-9][0-9]" logs/

# Summarize tool usage frequency
grep "Tool:" logs/3M_2017_10K_*.txt | awk '{print $2}' | sort | uniq -c | sort -rn

# List all final answers
grep "Predicted:" logs/3M_2017_10K_*.txt
```

## Common Failure Patterns

**Full sentence returned instead of a value** — Tighten the system prompt instruction: add an explicit example of the expected short-form answer format.

**Number hallucinated without tool call** — Check `tools_used`; if `search_tables` and `calculate` are both absent, the model answered from training data. Add to system prompt: "Never state a number without first calling search_tables."

**Table data missed** — The `search_tables` tool searches `table_data.cells`. If the keyword doesn't match any cell text exactly, try a shorter or alternate keyword (e.g., `"revenue"` instead of `"total net revenue"`).

**Wrong section retrieved** — Check `path_text` in the trace. Tighten the `filter_spans` call to filter by a more specific `path_text` substring.
